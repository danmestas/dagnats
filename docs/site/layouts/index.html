Durable workflows.

Just NATS.

dagnats runs graphs of tasks, agent loops and human approvals. It retries what fails and resumes after a crash, with NATS JetStream embedded in the same process. No Postgres, no Redis, no broker to run.

Everything a workflow engine needs. Nothing it has to depend on.

State is an event log in JetStream with snapshots in KV. Kill the process, start it again, and in-flight work picks up from the last event.

01

One binary, zero databases

Deploy is scp and serve. No migrations, no Redis to operate, no broker to configure.

02

Crash-safe by default

Every transition is an event in JetStream. A restart replays to the last one and carries on.

03

Agent steps are first-class

AgentLoop, Planner, Approval and WaitForEvent are step types, not patterns you rebuild per project.

04

Inspectable to the byte

Every event is a JSON message on a subject. Tail any run live from any terminal.

05

Bounded everywhere

No unbounded queues, retries or recursion. Every loop has a fixed upper limit.

06

Clusters when you need them

Three or five nodes, every stream replicated, routes over your private network. Leases and leader election built in.

How it fits together

All state lives in JetStream and KV. That is the whole system.

01 · triggers
Cron, webhooks, subjects, run-terminal

Each fire becomes an event on the history stream, deduplicated by message ID.

02 · orchestrator
Consume event, advance the DAG, snapshot

Timeouts, sleeps and retries are timers on a stream, not a scheduler you run.

03 · workers
Pull tasks, report results

Go workers in-process or anywhere on NATS; anything else over the HTTP bridge.

What it is not

dagnats is young and single-tenant by design. There is one Go SDK plus an HTTP bridge; a native TypeScript or Python SDK is yours to write.

Skip it for sub-millisecond task routing (use a queue), for dependency-free batch jobs (use a worker pool), and where eventual consistency would surprise you (use a database with transactions).

Run it before your coffee cools.
